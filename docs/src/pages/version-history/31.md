title: Version 3.1

## Released December 2017

## Licensing Changes

*   MusicXML 3.1 is now licensed under the W3C Community Final Specification Agreement rather than the MusicXML Public License 3.0. ([Issue 114](https://github.com/w3c-cg/musicxml/issues/114))

## Packaging Changes

*   MusicXML 3.1 now recommends .musicxml rather than .xml as the file extension for uncompressed MusicXML files. ([Issue 191](https://github.com/w3c-cg/musicxml/issues/191))
*   MusicXML 3.1 adds a new file called mimetype as the first file in the zip container of a compressed MusicXML file. The file is uncompressed and has the string application/vnd.recordare.musicxml as its content. ([Issue 185](https://github.com/w3c-cg/musicxml/issues/185))
*   MusicXML 3.1 files now have recommended Uniform Type Identifiers. ([Issue 50](https://github.com/w3c-cg/musicxml/issues/50))

## Schema Additions

### New Elements

*   The [<arrowhead>](../../musicxml-reference/elements/arrowhead/) element represents arrowheads without an arrow stem. ([Issue 183](https://github.com/w3c-cg/musicxml/issues/183))
*   The [<beat-unit-tied>](../../musicxml-reference/elements/beat-unit-tied/) element represents tied notes in regular metronome marks. ([Issue 92](https://github.com/w3c-cg/musicxml/issues/92))
*   The [<brass-bend>](../../musicxml-reference/elements/brass-bend/) element represents the u-shaped bend symbol used in brass notation. ([Issue 44](https://github.com/w3c-cg/musicxml/issues/44))
*   The [<credit-symbol>](../../musicxml-reference/elements/credit-symbol/) element specifies a musical symbol using a canonical SMuFL glyph name. It is used when an occasional musical symbol is interspersed into text. ([Issue 163](https://github.com/w3c-cg/musicxml/issues/163))
*   The [<except-voice>](../../musicxml-reference/elements/except-voice/) element is used to specify a combination of slash notation and regular notation. ([Issue 231](https://github.com/w3c-cg/musicxml/issues/231))
*   The [<figure>](../../musicxml-reference/elements/figure/) element may now have the [<footnote>](../../musicxml-reference/elements/footnote/) and [<level>](../../musicxml-reference/elements/level/) elements as optional child elements. ([Issue 94](https://github.com/w3c-cg/musicxml/issues/94))
*   The [<flip>](../../musicxml-reference/elements/flip/) element represents the flip symbol used in brass notation. ([Issue 44](https://github.com/w3c-cg/musicxml/issues/44))
*   The [<glyph>](../../musicxml-reference/elements/glyph/) element represents what SMuFL glyph should be used for different variations of symbols that are semantically identical. ([Issue 64](https://github.com/w3c-cg/musicxml/issues/64), [Issue 71](https://github.com/w3c-cg/musicxml/issues/71), [Issue 72](https://github.com/w3c-cg/musicxml/issues/72))
*   The [<golpe>](../../musicxml-reference/elements/golpe/) element represents the golpe symbol that is used for tapping the pick guard in guitar music. ([Issue 100](https://github.com/w3c-cg/musicxml/issues/100))
*   The [<half-muted>](../../musicxml-reference/elements/half-muted/) element represents the half-muted symbol which looks like a circle with a plus sign inside. ([Issue 44](https://github.com/w3c-cg/musicxml/issues/44))
*   The [<harmon-mute>](../../musicxml-reference/elements/harmon-mute/) element represents the symbols used for harmon mutes in brass notation. ([Issue 44](https://github.com/w3c-cg/musicxml/issues/44))
*   The [<haydn>](../../musicxml-reference/elements/haydn/) element represents the Haydn ornament, defined in SMuFL as ornamentHaydn. ([Issue 95](https://github.com/w3c-cg/musicxml/issues/95))
*   The [<inverted-vertical-turn>](../../musicxml-reference/elements/inverted-vertical-turn/) element represents the turn symbol shape arranged vertically going from upper left to lower right. ([Issue 95](https://github.com/w3c-cg/musicxml/issues/95))
*   The [<metronome-arrows>](../../musicxml-reference/elements/metronome-arrows/) element indicates the presence of metric modulation arrows on both sides of the metronome mark. ([Issue 93](https://github.com/w3c-cg/musicxml/issues/93))
*   The [<metronome-tied>](../../musicxml-reference/elements/metronome-tied/) element represents tied notes in metric modulations and other metric relationships. ([Issue 92](https://github.com/w3c-cg/musicxml/issues/92))
*   The [<n>](../../musicxml-reference/elements/n/) element represents an n dynamic. ([Issue 52](https://github.com/w3c-cg/musicxml/issues/52))
*   A single [<note>](../../musicxml-reference/elements/note/) element may now have both [<cue>](../../musicxml-reference/elements/cue/) and [<grace>](../../musicxml-reference/elements/grace/) child elements. ([Issue 68](https://github.com/w3c-cg/musicxml/issues/68))
*   The [<open>](../../musicxml-reference/elements/open/) element represents the open symbol, which looks like a circle. ([Issue 44](https://github.com/w3c-cg/musicxml/issues/44))
*   The [<pf>](../../musicxml-reference/elements/pf/) element represents a pf dynamic. ([Issue 52](https://github.com/w3c-cg/musicxml/issues/52))
*   The [<sfzp>](../../musicxml-reference/elements/sfzp/) element represents an sfzp dynamic. ([Issue 52](https://github.com/w3c-cg/musicxml/issues/52))
*   The [<smear>](../../musicxml-reference/elements/smear/) element represents the tilde-shaped smear symbol used in brass notation. ([Issue 44](https://github.com/w3c-cg/musicxml/issues/44))
*   The [<soft-accent>](../../musicxml-reference/elements/soft-accent/) element indicates a soft accent that is not as heavy as a normal accent. It is often notated as <>. ([Issue 131](https://github.com/w3c-cg/musicxml/issues/131))
*   The [<staff-divide>](../../musicxml-reference/elements/staff-divide/) element represents staff division arrow symbols. ([Issue 11](https://github.com/w3c-cg/musicxml/issues/11))
*   The [<symbol>](../../musicxml-reference/elements/symbol/) element specifies a musical symbol using a canonical SMuFL glyph name. It is used when an occasional musical symbol is interspersed into text. ([Issue 163](https://github.com/w3c-cg/musicxml/issues/163))

## Removed and Deprecated Features

*   The font-family, font-size, font-style, and font-weight attributes have been removed from the [<extend>](../../musicxml-reference/elements/extend/) element. The <extend> element contains no text, and these attributes were added by mistake in MusicXML 1.1. ([Issue 140](https://github.com/w3c-cg/musicxml/issues/140))
*   The bezier-offset and bezier-offset2 attributes are deprecated as of MusicXML 3.1. ([Issue 26](https://github.com/w3c-cg/musicxml/issues/26))

## Documentation Changes

MusicXML 3.1 made the following changes to the XSD and DTD schema documentation.

*   The DTD documentation for the [<actual-notes>](../../musicxml-reference/elements/actual-notes/) and [<normal-notes>](../../musicxml-reference/elements/normal-notes/) elements has been corrected to fix a typo. ([Issue 138](https://github.com/w3c-cg/musicxml/issues/138))
*   The XSD and DTD documentation for the [<accordion-high>](../../musicxml-reference/elements/accordion-high/), [<accordion-low>](../../musicxml-reference/elements/accordion-low/), and [<accordion-middle>](../../musicxml-reference/elements/accordion-middle/) elements clarifies that the elements are omitted if no dots are present. ([Issue 134](https://github.com/w3c-cg/musicxml/issues/134))
*   The XSD and DTD documentation for the attack and release attributes and their interrelationship has been clarified. ([Issue 58](https://github.com/w3c-cg/musicxml/issues/58))
*   The XSD and DTD documentation for the bezier-x, bezier-y, bezier-x2, bezier-y2, bezier-offset, and bezier-offset2 attributes and their interrelationships has been clarified. ([Issue 25](https://github.com/w3c-cg/musicxml/issues/25), [Issue 26](https://github.com/w3c-cg/musicxml/issues/26))
*   The cancel complex type XSD documentation now describes the location attribute correctly. ([Issue 18](https://github.com/w3c-cg/musicxml/issues/18))
*   The [<cue>](../../musicxml-reference/elements/cue/) element XSD and DTD documentation clarifies that the <cue> element indicates silent notes. ([Issue 67](https://github.com/w3c-cg/musicxml/issues/67))
*   The [<direction>](../../musicxml-reference/elements/direction/) element XSD and DTD documentation clarifies the relationship between <direction> and [<note>](../../musicxml-reference/elements/note/) elements. ([Issue 170](https://github.com/w3c-cg/musicxml/issues/170))
*   The [<falloff>](../../musicxml-reference/elements/falloff/) element XSD documentation has been corrected to indicate the falloff comes after the note. ([Issue 17](https://github.com/w3c-cg/musicxml/issues/17))
*   The interchangeable complex type XSD documentation no longer refers to a non-existent parentheses attribute. ([Issue 12](https://github.com/w3c-cg/musicxml/issues/12))
*   The [<key-octave>](../../musicxml-reference/elements/key-octave/) element XSD and DTD documentation clarifies the behavior of the cancel attribute. ([Issue 126](https://github.com/w3c-cg/musicxml/issues/126))
*   The multiple-rest complex type XSD documentation no longer refers to a non-existent type attribute. ([Issue 15](https://github.com/w3c-cg/musicxml/issues/15))
*   The note-type complex type XSD documentation now refers to 1024th to maxima instead of 256th to long. ([Issue 16](https://github.com/w3c-cg/musicxml/issues/16))
*   The [number-level](../../musicxml-reference/data-types/number-level/) simple type XSD documentation now refers to an optional rather than implied value. ([Issue 19](https://github.com/w3c-cg/musicxml/issues/19))
*   The [string-number](../../musicxml-reference/data-types/string-number/) simple type and [<string>](../../musicxml-reference/elements/string/) element XSD and DTD documentation clarifies how string numbers are ordered. ([Issue 127](https://github.com/w3c-cg/musicxml/issues/127))
*   The [<tied>](../../musicxml-reference/elements/tied/) element XSD and DTD documentation clarifies how to represent different types of single-ended tie symbols. ([Issue 142](https://github.com/w3c-cg/musicxml/issues/142))
*   The [<wavy-line>](../../musicxml-reference/elements/wavy-line/) element XSD and DTD documentation now refers to [<barline>](../../musicxml-reference/elements/barline/) rather than [<measure>](../../musicxml-reference/elements/measure-partwise/) elements. ([Issue 13](https://github.com/w3c-cg/musicxml/issues/13))
